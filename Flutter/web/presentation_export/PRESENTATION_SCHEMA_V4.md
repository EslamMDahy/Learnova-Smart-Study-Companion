# Learnova Instructor Presentation Schema v4

This schema is designed for **teaching sequences**, not a gallery of repeated cards. The AI selects a semantic layout for each teaching purpose; Flutter generates canonical 16:9 geometry; the same elements are converted by `dom-to-pptx` into editable PowerPoint text boxes and shapes.

## Deck contract

```json
{
  "schema_version": 4,
  "title": "Lecture title",
  "slides": []
}
```

Each slide requires `slide_number`, `layout_type`, and `title`. Keep one main teaching idea per slide. Split dense content into additional slides instead of shrinking it.

## AI authoring rules

1. Build a teaching sequence, not a component gallery: cover → objectives → concept blocks → examples/application → formative check → summary → references.
2. Choose the layout from the teaching purpose. Do not use `adaptive_cards` as the default for every slide.
3. Keep lecture slides readable from a classroom screen. The renderer rejects content that exceeds the safe limits instead of silently deleting it.
4. Use a separate slide for each major idea, derivation, worked example, or question reveal.
5. Prefer diagrams, comparisons, tables, timelines, and visuals where they communicate the idea better than prose.
6. Put presenter detail in concise fields or speaker notes generated by the app, not in oversized slide paragraphs.
7. For quizzes, use a question slide with `show_answer: false`, followed by an explanation slide when the answer should not be visible immediately.

### Safe content limits

- Objectives: 6
- Key points: 5
- Comparison points per side: 5
- Process or timeline items: 6
- Diagram nodes / edges: 12 / 20
- Table columns / rows: 6 / 8
- Equation derivation steps: 5
- Worked-example solution steps: 3
- Other problem-solution steps: 5
- Multiple-choice options: 2–4
- Activity instructions: 5
- Case-study questions: 2
- Summary points: 6
- References: 12
- Legacy/adaptive cards: 12, but 3–5 concise items are recommended for classroom use

## Supported layouts

| Layout | Best use | Main JSON field |
|---|---|---|
| `title_slide` | Lecture cover | `subtitle`, `course`, `instructor`, `term`, optional `visual` |
| `lecture_objectives` | Measurable outcomes | `objectives` |
| `section_divider` | Start a new section | `section_number`, `subtitle` |
| `concept_explanation` | Explain one concept | `content.lead`, `content.body`, `content.bullets` |
| `text_with_image` | Explain beside a visual | `content`, `visual` |
| `full_image` | Visual pause or story | `visual`, `subtitle` |
| `key_points` | 3–5 high-value takeaways | `cards` or `points` |
| `comparison` | Contrast two ideas | `comparison.left`, `comparison.right` |
| `process_steps` | Method or workflow | `process` |
| `timeline` | Chronological development | `timeline` |
| `diagram` | Concept map or flow | `diagram.nodes`, `diagram.edges` |
| `table` | Structured comparison/data | `table.headers`, `table.rows` |
| `equation_explanation` | Introduce one equation | `equation`, `content.bullets` |
| `equation_derivation` | Show derivation steps | `equation.steps` |
| `worked_example` | Given → formula → substitution → answer | `problem` |
| `problem_solution` | Problem beside solution path | `problem` |
| `multiple_choice` | Formative question | `problem.choices` |
| `practice_activity` | Student task | `activity` |
| `case_study` | Context, challenge, evidence, discussion | `case_study` |
| `quote` | Conceptual pause | `quote` |
| `summary` | Close the lecture | `summary` |
| `references` | Sources and further reading | `references` |
| `adaptive_cards` | Small content groups only | `cards` |
| `single_card_center` | One focused card | `cards` |
| `two_card_horizontal` | Two concise cards | `cards` |
| `three_card_horizontal` | Three concise cards | `cards` |

## Images

```json
{
  "visual": {
    "src": "assets/diagrams/neuron.png",
    "fit": "contain",
    "position": "right",
    "caption": "A biological neuron and its main structures.",
    "alt": "Labeled neuron diagram"
  }
}
```

- Local Flutter assets use paths such as `assets/book.webp`.
- Keep all local files under the project `assets/` folder and declare that folder in `pubspec.yaml`.
- Remote HTTPS images must allow browser CORS. For protected course images, return a same-origin URL or a data URL from the backend.
- Images remain image objects in PowerPoint. Text, captions, panels, and decorations remain editable native objects.

## Equations

Simple equations should use editable text:

```json
{
  "equation": {
    "latex": "F = ma",
    "render_mode": "text",
    "explanation": "Force equals mass multiplied by acceleration."
  }
}
```

Complex LaTeX should use local MathJax SVG rendering:

```json
{
  "equation": {
    "latex": "P(A\\mid B)=\\frac{P(B\\mid A)P(A)}{P(B)}",
    "render_mode": "svg"
  }
}
```

- `text`: editable PowerPoint text box.
- `svg`: scalable vector equation image; surrounding explanation remains editable.
- `auto`: complex LaTeX becomes SVG, plain expressions remain text.
- Native Microsoft Office Math/OMML is not generated by `dom-to-pptx`.

## Worked example

```json
{
  "layout_type": "worked_example",
  "title": "Find the force",
  "problem": {
    "statement": "A 5 kg object accelerates at 3 m/s². Find the force.",
    "given": ["m = 5 kg", "a = 3 m/s²"],
    "formula": "F = ma",
    "solution_steps": ["F = 5 × 3", "F = 15 N"],
    "final_answer": "15 N"
  }
}
```

## Multiple choice and answer reveal

Set `show_answer` to `false` for a question slide and create a following answer/explanation slide. Set it to `true` only when the correct choice should be highlighted in the exported deck.

## RTL

Arabic is detected per text element. English uses Lexend/Inter; Arabic uses an Arabic-capable PowerPoint font fallback. Avoid mixing full Arabic and English paragraphs in one field when separate fields are possible.

```text

assets/fonts/Inter-Bold.ttf

```
